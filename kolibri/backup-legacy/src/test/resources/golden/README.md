# Golden backups

Test resources for the frozen legacy-ZIP read path of the shared backup engine
(SPEC_NYX_REWRITE, section "Golden-Set"). Each case is a pair:

- `<app>-<case>.zip` — a backup written by today's app (legacy ZIP format:
  `backup.json` + `wallpapers/layer_N.img`).
- `<app>-<case>.expected.json` — the state after importing it under the NEW
  semantics (E1, E2, B11, B13, B14), not what today's app would produce. Every
  difference from today's import result must map to a row in the spec's
  "Nutzersichtbare Änderungen".

Conventions of `expected.json`:

- `installed` states which components the test's fake installed set contains.
- Sets (`favorites`, `hiddenComponents`) are sorted; ordered lists keep order.
- Wallpaper blobs are identified by `blobSha256` of the blob in the ZIP, never by
  URI (restored URIs are generated per import).

- `targetBefore` is the target's state before import where a case depends on it
  (`<any>` otherwise); `<unchanged>` in `expected` means "equal to targetBefore".
- `importer` is the app that imports (`kolibri` or `nyx`).

All files except `kolibri-voll.zip` are generated by
`tools/golden/derive_kolibri_cases.py` (deterministic; re-run after changing a
semantic decision, never edit the outputs by hand). The whole directory moves
into `:kolibri:backup-legacy` test resources in Phase 2a (done in 2a-6: this
directory) and is deleted with that module at sunset.

Privacy: the repo is public. Real device backups are never committed; they go
through `tools/golden/anonymize_kolibri_backup.py` first (package names, custom
names and wallpaper images are replaced, structure is kept).
